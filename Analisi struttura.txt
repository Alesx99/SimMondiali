## 1. Sicurezza e Backend (`server.js`)

Il server HTTP in Node.js è leggero e funzionale, ma presenta alcune vulnerabilità e limitazioni tecniche importanti:

### A. Vulnerabilità di Directory Traversal (Parziale Folder Name Traversal)
*   **Problema**: Alla riga 29 di `server.js`, la condizione `if (!filePath.startsWith(__dirname))` è debole. Se la cartella del progetto si chiama `/Mondiali` e sullo stesso livello esiste una cartella chiamata `/Mondiali-segreti`, una richiesta HTTP verso `../Mondiali-segreti/file.txt` supererà il controllo perché il percorso risultante inizia con la stessa stringa di `__dirname`.
*   **Miglioramento**: Risolvere i percorsi in modo assoluto e verificare che il percorso richiesto si trovi effettivamente all'interno della directory del progetto aggiungendo il separatore di sistema.
*   **Soluzione**:
    ```javascript
    const safePath = path.resolve(filePath);
    const baseDirectory = path.resolve(__dirname);
    if (!safePath.startsWith(baseDirectory + path.sep) && safePath !== baseDirectory) {
        res.writeHead(403, { 'Content-Type': 'text/html' });
        res.end('<h1>403 Forbidden</h1>');
        return;
    }
    ```

### B. Gestione dei Parametri di Query
*   **Problema**: Il server non rimuove i parametri di query (es. `?v=1.0`) o le ancore hash dall'URL prima di cercare i file sul disco. Una richiesta come `/style.css?v=1` fallisce con un errore `404 File Not Found` perché cerca sul file system un file chiamato letteralmente `style.css?v=1`.
*   **Miglioramento**: Estrarre solo il `pathname` dall'URL prima di comporre `filePath`.
*   **Soluzione**:
    ```javascript
    const parsedUrl = new URL(req.url, `http://${req.headers.host || 'localhost'}`);
    let urlPath = decodeURIComponent(parsedUrl.pathname);
    let filePath = path.join(__dirname, urlPath === '/' ? 'index.html' : urlPath);
    ```

### C. Encoding dei File Binari
*   **Problema**: Il metodo `fs.readFile` invia tutti i contenuti forzando l'encoding `'utf-8'` (`res.end(content, 'utf-8')`). Questo corrompe i file binari, rendendo illegibili immagini (`.png`, `.jpg`) o documenti PDF (come `tabellone-fase-eliminazione-mondiali-2026.pdf`).
*   **Miglioramento**: Rimuovere l'argomento `'utf-8'` per inviare i file binari come `Buffer` nativo e aggiornare la lista `MIME_TYPES` inserendo le estensioni `.docx` e `.odt` presenti nella cartella.

## 2. Qualità del Codice e Architettura (`app.js`)

Il codice di `app.js` contiene l'intera logica di simulazione ma soffre di problemi di accoppiamento e scalabilità:

### A. Esternalizzazione del Database (`TEAMS_DB`)
*   **Problema**: `TEAMS_DB` occupa circa **4.000 righe** di codice cablato direttamente all'interno di `app.js`. Questo rende il caricamento del file JavaScript pesante per il browser ed ostacola modifiche esterne ai dati delle squadre o ai rating dei giocatori.
*   **Miglioramento**: Spostare l'intero database in un file JSON esterno (es. `/data/teams_db.json`) e caricarlo asincronamente all'avvio dell'applicazione.
*   **Soluzione**:
    ```javascript
    // All'avvio dell'applicazione
    const teamsRes = await fetch('/data/teams_db.json');
    const TEAMS_DB = await teamsRes.json();
    ```

### B. Tolleranza ai Guasti durante l'Inizializzazione
*   **Problema**: L'app utilizza `Promise.all` per caricare le statistiche asincrone. Se uno solo dei file JSON (`squad_values.json`, `h2h_stats.json`, ecc.) restituisce un errore 404 o non è formattato correttamente, l'intero blocco fallisce e blocca l'inizializzazione di tutta l'applicazione (partite, classifiche e tabellone non vengono mostrati).
*   **Miglioramento**: Utilizzare `Promise.allSettled` o blocchi `try/catch` individuali per evitare che il fallimento di un archivio storico blocchi il simulatore principale.

### C. Persistenza dello Stato
*   **Problema**: Punteggi simulati, modifiche alle formazioni (lineup) e nuovi giocatori creati vengono persi al rinfresco della pagina.
*   **Miglioramento**: Salvare le variabili di stato (`matches`, `knockoutMatches`, `TEAMS_DB` modificato) su `localStorage` in modo da ripristinare la sessione di simulazione dell'utente.

## 3. Logica Matematica e Algoritmi (Bug Critici in `app.js`)

L'analisi dell'algoritmo di quote e probabilità ha evidenziato due bug che possono compromettere i calcoli matematici:

### Bug 1: Valori NaN nelle Quote per Underflow Floating-Point
*   **Problema**: Se c'è una differenza estrema di valore/rating tra le due squadre, il calcolo dei gol attesi (`lambdaA` o `lambdaB`) può salire molto. Nel modello di Poisson, se `lambda` è alto (es. > 150), `Math.exp(-lambda)` restituisce esattamente `0` (underflow). Questo azzera tutti gli elementi della distribuzione, portando `sumA` a `0`. Successivamente, la riga `distA[g] /= sumA` causa una divisione `0/0` che riempie l'array di valori `NaN`. Questo errore si propaga a cascata a tutte le quote del match.
*   **Miglioramento**: Limitare il valore massimo di `lambda` ad un livello realistico per una partita di calcio (es. massimo 8.0 gol attesi) e validare che la somma sia maggiore di zero prima di dividere.
*   **Soluzione**:
    ```javascript
    let lambdaA = ...;
    lambdaA = Math.min(8.0, Math.max(0.1, lambdaA)); // Tetto massimo protettivo
    ```

### Bug 2: Percentuali di Pareggio Negative ed Anomalia Quota `1.01`
*   **Problema**: Il calcolo di `pctX` (probabilità del pareggio) è calcolato per sottrazione: `const pctX = 100 - pctA - pctB`. A causa di arrotondamenti o dell'aggiunta del fattore Bayesiano per lo storico H2H, la somma di `pctA` e `pctB` può superare 100% (es. `51` e `51`), facendo sì che `pctX` diventi negativo (es. `-2%`). Questo genera due problemi:
    1.  La UI mostra scritte incoerenti come "Pareggio -2%".
    2.  Nel calcolo della quota `oddX`, la divisione per un valore negativo restituisce un numero negativo che viene poi corretto da `Math.max(1.01, valore_negativo)` a `1.01`. Questo fa sì che per una partita equilibrata il sistema consigli una quota di pareggio di `1.01` (considerandolo quasi certo), che è un grave errore per un betting advisor.
*   **Miglioramento**: Assicurare che `pctX` non scenda mai sotto lo zero e normalizzare le tre probabilità affinché la somma sia sempre esattamente 100%.
*   **Soluzione**:
    ```javascript
    let pctA = Math.round(winA * 100);
    let pctB = Math.round(winB * 100);
    let pctX = Math.max(0, 100 - pctA - pctB);
    
    // Ricalibrazione per assicurare somma = 100%
    const totale = pctA + pctB + pctX;
    if (totale !== 100) {
        // Aggiusta la differenza sulla quota più alta o sul pareggio
    }
    ```

## 4. Esperienza Utente, CSS e Grafica (`index.html` e `style.css`)

### A. Il Bug della Schedina Invisibile su Dispositivi Mobili (CRITICO)
*   **Problema**: Nelle media query per schermi con larghezza inferiore a 1200px, la sidebar `.bet-slip-sidebar` (la schedina combinata) riceve la regola `display: none;`.             display: flex;
    ```css
            transform: translateX(110%);

            position: fixed;
            bottom: 0; right: 0;
            width: 100%; max-width: 380px; height: 80vh;
            z-index: 999;
        }

    }
    ```

### B. Compressione dei Tab su Schermi Piccoli
*   **Problema**: La barra `.tab-navigation` forza tutte le 5 schede su una singola riga senza andare a capo. Su schermi piccoli (< 480px), i testi dei pulsanti si sovrappongono o vengono troncati orrendamente (es. "Tabellone Fasi Finali").
*   **Miglioramento**: Abilitare lo scorrimento orizzontale della barra di navigazione su mobile, permettendo all'utente di scorrere le schede con il dito mantenendo intatta la leggibilità del testo.
*   **Soluzione CSS**:
    ```css
    @media (max-width: 768px) {

            overflow-x: auto;
            white-space: nowrap;
            display: flex;
            gap: 10px;
        }
        .tab-btn { flex: 0 0 auto; }
    }
    ```

### C. Accessibilità (WCAG AA) e Contrasto cromatico
*   **Contrasto del testo**: Il colore del testo `--text-muted: #64748b` usato su sfondo grigio scuro ha un rapporto di contrasto di **2.44:1**, ben al sotto del limite di accessibilità WCAG AA (**4.5:1**). Questo rende le date dei match e le descrizioni secondarie difficili da leggere. Si consiglia di cambiarlo in `#8b9bb4`.
*   **Associazione delle Label nel Form**: Nel modulo di creazione del giocatore nella modale, i tag `<label>` non sono associati agli input tramite l'attributo `for="..."`, impedendo agli screen reader di associare correttamente i campi.
*   **Pulsanti Iconografici**: Il pulsante di chiusura della modale contiene solo l'icona `xmark` di FontAwesome. Va aggiunto un attributo `aria-label="Chiudi"` per renderlo comprensibile agli ipovedenti.

### D. Connessioni Grafiche del Tabellone (Bracket)
*   **Problema**: Le schede del tabellone ad eliminazione diretta fluttuano all'interno delle rispettive colonne senza alcuna linea visiva di collegamento. È difficile per l'utente capire graficamente quale partita generi il turno successivo.
*   **Miglioramento**: Aggiungere linee di collegamento orizzontali e verticali utilizzando pseudo-elementi CSS (`::after`/`::before`) o un livello SVG di sfondo.
